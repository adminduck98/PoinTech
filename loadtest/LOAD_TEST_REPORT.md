## Анализ найденных проблем

### Проблема 1: Поиск товаров — 404 (КРИТИЧЕСКАЯ)

**Симптом:** Все запросы поиска возвращают 404.

**Причина:** PostgREST-фильтр `or=(name->ru.ilike.%%25час%25,...)` не работает через прямой REST-запрос. Хотя в клиентском коде (`src/lib/supabase/products.ts:53`) используется `.or()` с `ilike`, REST-формат URL отличается от формата Supabase JS-клиента.

**Влияние:** ~10% всех запросов приложения. Поиск товаров полностью неработоспособен через REST API.

**Решение:**
```sql
-- Создать RPC-функцию для поиска товаров
CREATE OR REPLACE FUNCTION search_products(p_query text)
RETURNS SETOF products AS $$
  SELECT * FROM products
  WHERE is_active = true
    AND (
      name->>'ru' ILIKE '%' || p_query || '%'
      OR name->>'uz' ILIKE '%' || p_query || '%'
      OR description->>'ru' ILIKE '%' || p_query || '%'
      OR description->>'uz' ILIKE '%' || p_query || '%'
    )
  ORDER BY created_at DESC
  LIMIT 20;
$$ LANGUAGE sql STABLE;
```

### Проблема 2: Checkout Edge Function — 404 (КРИТИЧЕСКАЯ)

**Симптом:** Все запросы checkout возвращают 404 (не 500, не 400).

**Причина:** Edge Function `checkout` не доступна по URL `${SUPABASE_URL}/functions/v1/checkout`. Возможные причины:
- Функция не задеплоена или была удалена
- Имя функции в Supabase отличается от `checkout`
- Функция находится в другом проекте Supabase

**Влияние:** ~3.3% всех запросов. Пользователи не могут оформлять заказы.

**Решение:**
```bash
# Проверить деплой функции
supabase functions list --project-ref wrjixyedostqulufnjpw

# Передеплоить если нужно
supabase functions deploy checkout --project-ref wrjixyedostqulufnjpw
```

### Проблема 3: Rate Limiter в client-api (СРЕДНЯЯ)

**Симптом:** Rate limiter (`30 req/min per IP`) блокирует запросы с одного IP.

**Причина:** В `supabase/functions/client-api/index.ts:11-13` установлен лимит 30 запросов в минуту на IP. При нагрузочном тесте все запросы идут с одного IP.

**Влияние:** В продакшене это не проблема (у каждого пользователя свой IP), но при горизонтальном масштабировании (API gateway) может стать узким местом.

**Решение:** Добавить rate limiting по `telegram_user_id` вместо IP:
```typescript
function checkRateLimit(identifier: string): boolean {
  // Use telegram_user_id instead of IP for rate limiting
}
```

### Проблема 4: Медленные запросы (НИЗКАЯ)

**Симптом:** P99 = 1 744ms, максимальное время = 8 143ms.

**Причина:** Под нагрузкой 1000 пользователей PostgreSQL-соединения могут исчерпываться. Supabase Free tier имеет лимит 60 соединений, Pro — 200.

**Влияние:** ~1% запросов выполняются дольше 3 секунд.

**Решение:** Включить PgBouncer (connection pooling) в Supabase.
